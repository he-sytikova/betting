# Угловые и жёлтые карточки: аудит данных и модель

## Статус

Первый этап — автоматический аудит доступности статистики. Прогнозы пока не публикуются: сначала требуется подтвердить историческое покрытие и качество исходных данных.

## Источники

1. [open-matchday](https://github.com/oladeeayo/open-matchday) — текущий сезон 2026/27, 75 соревнований. CSV с результатами, угловыми, карточками и фолами там, где эти поля доступны. Бесплатно для некоммерческого использования с атрибуцией. Пустые значения не трактуются как нули.
2. [Football-data.co.uk](https://www.football-data.co.uk/data.php) — исторические CSV по ряду европейских лиг. Для аудита используются сезоны 2015/16–2025/26; угловые HC/AC и жёлтые карточки HY/AY учитываются только при наличии обеих сторон.
3. [El Colegiado](https://elcolegiado.com/data/) — отдельный кандидат для расширения исторической базы по Испании и фактора судьи. До отдельной проверки схемы, лицензии и дублей не включён в автоматическую загрузку.

## Запуск

Локально, Python 3.10+ без сторонних зависимостей:

```bash
python scripts/predictions/audit-data.py
```

Или GitHub Actions → **Audit corners and yellow-card data** → Run workflow.

Результат: `data/corners_cards_audit.json`.

## Правила допуска (начальные пороги)

- не менее 100 исторических матчей с нужной статистикой;
- не менее 8 матчей на каждую команду;
- не менее 80% заполненности нужного показателя в последних матчах команды;
- отдельный допуск для угловых и карточек.

Пороги будут проверены walk-forward тестированием и при необходимости изменены. Лига может пройти отбор для угловых, но не пройти для ЖК.

## Сбор обучающей выборки и первый backtest

После успешного аудита запустите GitHub Actions → **Build and backtest corners and cards models** → Run workflow.

Workflow:
1. Загружает исторические CSV Football-data.co.uk для лиг, допущенных аудитом отдельно для каждого рынка.
2. Строит признаки команд по предыдущим матчам (скользящие средние за 5 и 10 игр); результаты матчей того же календарного дня не попадают в признаки друг друга.
3. Обучает PoissonRegressor для среднего ожидаемого количества. Затем на той же отложенной выборке сравнивает распределения Пуассона и Negative Binomial (NB2), оценивая параметр сверхдисперсии только на обучающей части по остаткам Пуассона. Так сравнивается влияние сверхдисперсии при одинаковом прогнозе среднего, без нестабильной оценки второго набора коэффициентов на коррелирующих признаках.
4. Проверяет их на хронологической отложенной выборке начиная с 1 июля 2024 года и сравнивает с базовым средним лиги.\n5. Дополнительно выполняет expanding-window walk-forward по сезонам с датами начала 1 июля 2023, 2024, 2025 и 2026 года: для каждого сезона модель заново обучается только на матчах до его начала, а тестируется на матчах этого сезона. Недостаточно большие фолды отмечаются как пропущенные. По объединённым out-of-time прогнозам сравниваются NB2 и Пуассон по Brier Score и Log Loss; применяются парный permutation/sign-flip тест и поправка Холма отдельно по шести линиям для каждой метрики. В отчёте сохраняются метрики каждого фолда и общий результат.\n6. Для линий 7.5, 8.5, 9.5, 10.5, 11.5 и 12.5 рассчитывает вероятности ТБ/ТМ по распределениям Пуассона и Negative Binomial; для каждого направления считает Brier Score, Log Loss, фактическую частоту и калибровочные интервалы. Те же метрики рассчитываются для базового прогноза. Дополнительно отчёт сравнивает модель и базовый прогноз отдельно по каждой лиге и сезону (группы менее 100 матчей не показываются), а также оценивает отношение дисперсии фактического тотала к среднему как первичную диагностику сверхдисперсии.

Дополнительная диагностика:
- equal-frequency reliability bins по вероятностям ТБ/ТМ;
- ECE (Expected Calibration Error), MCE и Wilson 95% интервалы фактической частоты в бинах;
- коэффициенты PoissonRegressor по каждому walk-forward фолду, переведённые в исходные единицы признаков;
- устойчивость знака коэффициента, среднее, стандартное отклонение и число смен знака между фолдами.

Эти коэффициенты описывают условное среднее количества событий, а не напрямую вероятности ставок. Стабильность знака — диагностический сигнал, а не доказательство причинного влияния. ECE/MCE зависят от группировки и не заменяют Brier Score, Log Loss или проверку калибровки на новых сезонах.

Файлы:
- `data/corners_cards_training.csv` — обучающая выборка;
- `data/corners_cards_model_report.json` — метрики и параметры моделей, калибровка и коэффициенты по фолдам;
- `data/walk-forward-summary.json` — компактный summary walk-forward, устойчивости коэффициентов и holdout-калибровки (также доступен как Actions artifact).

Это исследовательский baseline. Brier Score и Log Loss оценивают качество вероятностей (меньше — лучше), а калибровочные интервалы показывают расхождение между средней прогнозируемой вероятностью и фактической частотой. Эти показатели сами по себе не доказывают прибыльность. ROI не рассчитывается без исторических коэффициентов; для допуска в приложение нужны дополнительные odds-aware проверки по сезонам, проверка маржи и отдельная калибровка рынков. Текущий walk-forward оценивает устойчивость статистической модели, но не прибыльность ставок.

## Следующие этапы

1. Проверить результаты аудита и выбрать соревнования с достаточной историей.
2. Нормализовать названия команд и идентификаторы соревнований, объединить источники без двойного учёта матчей.
3. Построить отдельные модели угловых и ЖК (Poisson и Negative Binomial как конкурирующие модели).
4. Выполнить walk-forward backtest без утечки будущих данных, сравнить с базовой частотой лиги и проверить калибровку. Negative Binomial сравнивается с Poisson по MAE, Poisson Deviance, Brier Score и Log Loss на тех же линиях и отложенной выборке.
5. Проверить устойчивость по лигам и сезонам, сравнить Brier Score и Log Loss модели с базовой частотой для каждой линии, отдельно изучить сверхдисперсию. Только после успешной проверки формировать `data/corners_cards_predictions.json` и подключать отдельную страницу в интерфейсе.

## Важные ограничения

- Текущий open-matchday сезон сам по себе не обеспечивает нужную глубину истории для обучения.
- Статистика угловых и карточек доступна не для всех матчей и лиг.
- Источники могут иметь разные написания команд и разные правила учёта статистики; дубли нужно удалять до обучения.
- Не публиковать прогноз для рынка, если у матча недостаточно данных именно по этому рынку.
- API-Football не используется.
